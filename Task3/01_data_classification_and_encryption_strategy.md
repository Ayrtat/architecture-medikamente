## Encryption at Rest

### Стратегия шифрования хранимых данных

#### 1. Файловый сервер (медицинские карты, сканы)

**Данные:** Папки пациентов, Excel-файлы, сканы документов

**Решение:**
- **BitLocker** для шифрования дисков (TPM)
- **EFS** для папок с L4 данными
- Windows Server 2022 поддерживает оба метода

**Обоснование:**
- Встроено в Windows Server
- Прозрачное шифрование (transparent)
- Интеграция с Active Directory
- Низкие накладные расходы (<5% производительности)

**Алгоритм:** AES-256-XTS (BitLocker), AES-256-CBC (EFS)

#### 2. Базы данных

**PostgreSQL (Primary DB):**
- **pgcrypto** для шифрования полей
- **Transparent Data Encryption (TDE)** для всей БД
- Шифрование резервных копий

**ClickHouse (Analytics DB):**
- Шифрование на уровне диска (dm-crypt/LUKS)
- Только обезличенные данные, но все равно шифровать

**1С Бухгалтерия/Торговля:**
- Миграция в клиент-серверный режим
- Шифрование на уровне СУБД (SQL Server TDE/PostgreSQL)
- Альтернатива: шифрование файла БД на уровне ОС

#### 3. Key Management Service (KMS)

**Решение:** HashiCorp Vault

**Функции:**
- Централизованное хранилище ключей
- Автоматическая ротация (90 дней)
- Audit всех операций с ключами
- HSM для master keys (опционально)

**Иерархия ключей:**
```
Master Key (HSM или Vault auto-unseal)
    ↓
Data Encryption Keys (DEK)
    ↓
Field-level keys (для токенизации)
```

#### 4. Резервные копии

**Требование:** Все backup должны быть зашифрованы

**Решение:**
- Veeam Backup с встроенным шифрованием (AES-256)
- Immutable backups (защита от ransomware)
- Шифрование при передаче в offsite storage

## Encryption in Transit

### Стратегия защиты данных при передаче

#### 1. Внутренняя сеть (Internal)

**HTTPS/TLS 1.3:**
- Все веб-интерфейсы
- API между микросервисами
- Сертификаты от внутреннего CA

**Конфигурация:**
```
TLS 1.3 only
Cipher suites: 
  - TLS_AES_256_GCM_SHA384
  - TLS_CHACHA20_POLY1305_SHA256
Perfect Forward Secrecy (PFS)
HSTS enabled
```

#### 2. Внешние соединения

**VPN (WireGuard):**
- Связь с внешней лабораторией
- Удаленный доступ сотрудников
- Site-to-site для филиалов

**Обоснование WireGuard:**
- Современный протокол
- Простая конфигурация
- Высокая производительность
- Встроенный в Linux kernel 5.6+

**Альтернатива:** IPSec для legacy систем

#### 3. Email

**S/MIME:**
- Сертификаты для шифрования email
- Только для критичной переписки
- Обучение пользователей

**Политика:**
- **ЗАПРЕЩЕНО** отправлять медицинские данные по email
- Использовать защищенный портал для обмена файлами
- DLP для блокировки ПД в email

#### 4. Мобильное приложение

**Защита:**
- Certificate Pinning
- TLS 1.3
- JWT токены с коротким TTL (15 мин)
- Refresh tokens в Secure Storage

## Автоматизированный контроль

### Инструменты контроля

#### 1. DLP (Data Loss Prevention)

**Microsoft Purview DLP:**

**Политики:**
- Блокировка отправки файлов с тегом [L4] по email
- Алерт при копировании медкарт на USB
- Блокировка скриншотов медданных (опционально)
- Мониторинг печати конфиденциальных документов

#### 2. SIEM (Security Information and Event Management)

**Graylog:**

**Мониторинг:**
- Неавторизованные попытки доступа
- Массовое скачивание файлов
- Доступ к данным не своих пациентов (для врачей)
- Экспорт больших объемов данных

**Алерты:**
- Real-time уведомления в Telegram/Email
- Escalation для критичных событий
- Integration с Incident Response процессом

#### 3. Vulnerability Scanning

**OpenVAS / Nessus:**
- Сканирование серверов на уязвимости
- Автоматические еженедельные проверки
- Отчеты с приоритизацией исправлений

#### 4. Compliance Monitoring

**Custom scripts + Apache Airflow:**

**Проверки:**
- Все ли файлы L4 зашифрованы?
- Ротация ключей выполнена?
- Backup созданы и зашифрованы?
- Логи сохранены за последние 6 месяцев?

**Метрики:**
- % зашифрованных файлов L3+
- Среднее время до обнаружения инцидента
- Количество алертов DLP
- Coverage audit логов

## Обоснование необходимости защиты

### Медицинские данные (L4)

**Почему критично:**
- Специальная категория ПД по ФЗ-152 ст.10
- Врачебная тайна по ФЗ-323 ст.13
- Наиболее чувствительные данные
- Риск компрометации здоровья и жизни

**Последствия утечки:**
- Штрафы до 500,000 руб (ФЗ-152)
- Уголовная ответственность (УК РФ ст.137)
- Потеря репутации
- Иски от пациентов

**Защита:**
- AES-256 at rest
- TLS 1.3 + VPN in transit
- ABAC (только лечащий врач)
- Полный audit

### ПД пациентов (L3)

**Почему важно:**
- Обычные ПД по ФЗ-152
- Могут быть использованы для fraud
- Обязательная защита по закону

**Последствия:**
- Штрафы до 300,000 руб
- Identity theft для пациентов
- Репутационный ущерб

**Защита:**
- AES-256 at rest
- TLS 1.3 in transit
- RBAC
- Audit + маскирование

### Финансовые данные (L2)

**Почему важно:**
- Коммерческая тайна
- Связь финансов с медицинскими данными может раскрыть диагнозы

**Последствия:**
- Финансовые потери
- Косвенное раскрытие медданных

**Защита:**
- Шифрование
- RBAC
- Базовый audit
