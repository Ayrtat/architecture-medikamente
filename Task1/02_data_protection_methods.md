## Методы защиты

### 1. Шифрование (Encryption)

**At Rest:**
- BitLocker для файлового сервера
- EFS для папок с медкартами
- Защита на уровне базы данных (TDE для 1С в клиент-серверном режиме)

**In Transit:**
- TLS 1.3 для всех сетевых соединений
- VPN для связи с внешней лабораторией
- S/MIME или PGP для email (если необходима передача)

### 2. Обфускация (Obfuscation)

**Маскирование:**
- В UI показывать неполные данные (Иван И*******)
- Маскирование номеров телефонов и счетов

**Токенизация:**
- Замена реальных значений на токены
- Хранение mapping в защищенном хранилище (Vault)

**Псевдонимизация:**
- UUID вместо ФИО в названиях файлов
- Patient_a3f2e1d9-4b5c/ вместо Pacient1-Ivanov-1990

### 3. Обезличивание (Anonymization)

**Для аналитики:**
- K-anonymity: группировка минимум 5-10 записей
- L-diversity: разнообразие в группах
- Differential Privacy: добавление шума
- Генерализация: точные даты -> периоды, возраст -> диапазоны
- Подавление: удаление уникальных комбинаций

**Для исследований:**
- Полное удаление прямых идентификаторов
- Агрегация данных
- Синтетические данные на основе реальных

## Контроль доступа

### RBAC (Role-Based Access Control)

| Роль | Доступ к медданным | Доступ к ПД | Доступ к финансам |
|------|-------------------|-------------|-------------------|
| Врач | Только свои пациенты (ABAC) | Минимально необходимые | Нет |
| Ресепшен | Нет (только демографические) | ФИО, контакты | Контракты |
| Кассир | Нет | ФИО (минимум) | Платежи |
| Бухгалтер | Нет | Минимум | Полный |
| IT-отдел | Нет доступа к расшифрованным | Нет | Нет |

### ABAC (Attribute-Based Access Control)

- Врач может читать карты только назначенных ему пациентов
- Временные ограничения доступа
- Break-the-glass для экстренных случаев с полным аудитом

## Аудит

- Логирование всех операций с файлами L3/L4
- SIEM для мониторинга аномалий
- Алерты при подозрительной активности
- Хранение логов минимум 6 месяцев (ФСТЭК)
